Синхронных тяжёлых вызовов до первого рендера не найдено: ни один провайдер не

## Реальные риски холодного старта

1. **Необработанная ошибка в цепочке диагностики запуска.** Любой отказ
   `beginLaunchDiagnostics`/`recordStartupChecks` (например, AsyncStorage
   недоступен) уводил `void (async () => …)` в unhandled rejection, маркер
   запуска не завершался — при повторении это ровно сценарий «повторный сбой
   Android release при холодном запуске» (todo 267) с растущим счётчиком
   `consecutiveFailures` и ложными уведомлениями о сбоях.
2. **Неограниченное ожидание гидрации.** Если нативный мост AsyncStorage
   зависает, `ready` хранилищ не выставляется никогда; интерфейс рендерился с
   значениями по умолчанию, а затем «прыгал» при подгрузке состояния.
3. Молчаливое проглатывание ошибок загрузки в хранилищах — ошибки не попадали
   в журнал диагностики запуска.

## Что изменено

- **`components/hydration-gate.tsx` (новый).** Лёгкий оверлей инициализации
  (`#0B0F0D`, ActivityIndicator `#C8F169`, подпись «IRONRISE») поверх контента,
  виден, пока гидрируются `workout-store` + `nutrition-store` + `body-store`.
  Таймаут **2,5 с**: по его истечении оверлей убирается и запуск продолжается
  в любом случае, в журнал пишется `warning` «Гидрация хранилищ превысила
  таймаут, запуск продолжен»; при штатной гидрации — `info` «Гидрация хранилищ
  завершена» (формат `launch-diagnostics` сохранён). Имен старого второго
  splash-слоя (`IronRiseLaunchSplash`, `launchSplashDuration` и т. п.) компонент
  не использует.
- **`app/_layout.tsx`.** Цепочка диагностики запуска обёрнута в `try/catch`:
  ошибка пишется в журнал через `reportStartupError(error, "Сбой диагностики
  запуска")` вместо необработанного reject. `HydrationGate` смонтирован внутри
  дерева провайдеров (после `ReleaseNotesOverlay`), поэтому на веб-версии
  накрывает только «телефон», а не весь браузерный холст.
- **Удалён `lib/launch-splash-settings.ts`** — мёртвый код без импортов;
  тестовые запреты на «Длительность заставки» в настройках остались в силе.

## Что осталось за пределами правки (наблюдение)

- `showRepeatedFailureNotification` при ≥2 подряд незавершённых запусках
  показывает локальное уведомление прямо на холодном старте — это не
  блокирует запуск, но при массовых сбоях добавляет работу на старте;
  оставлено как есть (поведение закреплено тестом `launch-diagnostics.test.ts`).
- Хранилища продолжают молча гасить ошибки загрузки: факт гидрации теперь
  виден в журнале запуска, но причина ошибки конкретного хранилища в журнал
  не пишется. Точка расширения — добавить `recordLaunchDiagnostic` в `.catch`
  хранилищ, если повторится сценарий «открылось с пустыми настройками».
