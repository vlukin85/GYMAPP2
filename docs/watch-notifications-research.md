# Управление тренировкой с часов Huawei (зеркалируемые уведомления)

## Зачем

Huawei Watch GT 6 (HarmonyOS) не запускает приложения Android-телефона напрямую:
уведомления Android зеркалируются на часы через Huawei Health. Это единственный
канал управления тренировкой «не доставая телефон». Подтверждённые ограничения
(см. `docs/huawei-gt6-research-notes.md`):

- кнопки-действия (`addAction`) уведомления на часы Huawei Health **не
  переносятся** — на зеркале виден только текст; управление сделано
  псевдокнопками (см. ниже);
- удалённый ввод текста (`RemoteInput`) на зеркальных уведомлениях не
  поддерживается — ввод результата подхода сделан карточками-корректировками.

## Псевдокнопки для Huawei

Почему: зеркалирование Huawei Health передаёт на часы только содержимое
уведомления (заголовок/текст), кнопки `addAction` остаются на телефоне. Это
платформенное ограничение цепочки «Android-телефон → Huawei Health → часы»,
подтверждённое сообществом: [Gadgetbridge issue #5552](https://github.com/Gadgetbridge/gadgetbridge/issues/5552)
(та же схема зеркалирования через Health — действия уведомлений на часы не
доходят).

Как работают карточки-действия: каждое действие оформлено **отдельным
уведомлением-карточкой**, чей `contentIntent` — broadcast `PendingIntent` на
`RestTimerActionReceiver` с нужным `ACTION_*`. Тап по карточке на часах
запускает `contentIntent` на телефоне и выполняет действие. Карточки не
`ongoing` (иначе не зеркалируются), у карточек-действий `PRIORITY_LOW`
(тихие, не вибрируют по пять раз подряд), у главной карточки «Готово» —
`PRIORITY_HIGH`; порядок задаётся `setSortKey` («Готово» — первая).

**Важная оговорка (план Б).** На части прошивок Huawei тап по зеркалированному
уведомлению открывает приложение, а не выполняет broadcast `contentIntent`.
Если на устройстве тап не выполняет действие — готовый fallback: заменить
`contentIntent` на deep-link `Activity` (`PendingIntent.getActivity` на
expo-router route, например `/workout?nativeAction=adjust-weight-up`), а
разбор параметра сделать на экране тренировки в `app/workout.tsx` рядом с
`consumeNativeRestTimerAction`. Broadcast-схема остаётся рабочей для телефона
и других оболочек; deep-link добавляется параллельно тем же набором `ACTION_*`.

## State machine уведомлений

```
[Подход выполняется 40108] --тап «Коснитесь, чтобы завершить подход»--> [Ввод результата 40109 + 40121–40125]
[Ввод результата] --тап «Готово» (40109)--> [Отдых 40101] --«Отдых завершён» + карточки 40131/40132--> ...
[Ввод результата] --тап «Отменить» (40125)--> назад к [Подход выполняется 40108]
```

Ввод результата — серия карточек-псевдокнопок, каждая = действие:

```
40109  «Готово»     PRIORITY_HIGH, sortKey 0 — «80 кг × 8 · коснитесь, чтобы подтвердить»
40121  «+5 кг»      PRIORITY_LOW,  sortKey 1 — contentIntent ACTION_ADJUST_WEIGHT_UP
40122  «−5 кг»      PRIORITY_LOW,  sortKey 2 — contentIntent ACTION_ADJUST_WEIGHT_DOWN
40123  «+1 повтор»  PRIORITY_LOW,  sortKey 3 — contentIntent ACTION_ADJUST_REPS_UP
40124  «−1 повтор»  PRIORITY_LOW,  sortKey 4 — contentIntent ACTION_ADJUST_REPS_DOWN
40125  «Отменить»   PRIORITY_LOW,  sortKey 5 — contentIntent ACTION_CANCEL_SET
```

Каждая корректировка обновляет `currentWeightKg`/`currentReps` и пере-постит
только карточку «Готово» (новые значения в тексте и в `contentIntent`);
карточки-действия статичны и не пере-постятся. Переключаемая раскладка «Ещё»
(`ACTION_MORE`) удалена за ненадобностью — все действия видны одновременно.

1. **Подход выполняется.** JS вызывает `showNativeRestCountdown`-подобную
   `showActiveSetNotification({ exerciseName, setIndex, setsCount,
   planWeightKg, planReps, exerciseIndex, exercisesCount, exerciseId })` в
   момент, когда `activeSet` появляется (`startSet`, авто-старт следующего
   подхода из нативного уведомления, восстановление черновика). Заголовок
   «Подход N из M · <Упражнение>», текст «План: 80 кг × 8 · Упражнение 2 из 5 ·
   Коснитесь, чтобы завершить подход». Псевдокнопка: `contentIntent` =
   broadcast `ACTION_FINISH_SET` (request code 40118); addAction «Завершить
   подход» остаётся для телефона. Кнопки отдыха («+30 сек») в этом состоянии
   не показываются. Уведомление обновляется при смене упражнения/подхода тем
   же вызовом (same notification id).
2. **Ввод результата.** `RestTimerActionReceiver` ловит `ACTION_FINISH_SET`,
   снимает уведомление подхода (40108) и постит серию карточек (40109,
   40121–40125). Текущие значения хранятся в статике receiver'а
   (`currentWeightKg`, `currentReps`), инициализируются планом и дублируются
   в extras каждого `PendingIntent` — если процесс умер, следующее нажатие
   восстанавливает значения из extras. «Готово» → `ACTION_COMMIT_SET`
   (contentIntent пересоздаётся при каждом обновлении значений);
   корректировки пере-постят только карточку «Готово»; шаг веса — 5 кг,
   повторов — 1, минимум 0 кг и 1 повтор.
3. **Отдых.** `ACTION_COMMIT_SET` сохраняет pendingAction с kind `commit-set`
   и финальными weight/reps (механизм `savePendingAction`/`consumePendingAction`
   — событий в модуле нет, JS опрашивает `consumeNativeRestTimerAction`), снимает
   все карточки результата. JS применяет значения тем же кодом, что и завершение
   подхода из интерфейса (`finishSetFromWatch` → общий `completeSetDraft` с
   `finishSetFromWidget`), после чего штатно запускается существующий отсчёт
   отдыха с действиями «Пропустить», «+30 секунд» и primary-действием
   «Следующий подход» / «Следующее упражнение».
4. **Отмена.** Карточка «Отменить» (40125, `ACTION_CANCEL_SET`): receiver
   снимает все карточки результата и заново показывает уведомление подхода с
   планом — значения сбрасываются к плану, JS-состояние не меняется (подход
   продолжает выполняться).
5. **Отдых завершён (40102).** Звуковое уведомление остаётся как есть (будит
   телефон) и дополняется тихими карточками-псевдокнопками в канале
   `ironrise-rest-complete-actions-v1`: «Следующий подход» (40131, contentIntent
   `ACTION_START` с теми же extras, что у addAction; постится, когда следующий
   шаг — подход) и «Следующее упражнение» (40132, contentIntent `ACTION_START`
   с `nextActionKind="finish-exercise"` — отдельной константы
   `ACTION_FINISH_EXERCISE` в модуле нет, переход упражнения выражается kind'ом
   `finish-exercise`). На телефоне панель становится тремя карточками —
   приемлемо. Карточки снимаются при следующем отсчёте, тапе по ним,
   «Пропустить» и завершении тренировки.

## Что работает при свёрнутом и убитом приложении

- Свёрнутое приложение (процесс жив): нативные ресиверы обрабатывают нажатия и
  пере-постят уведомления сами; JS подхватывает `commit-set` поллингом
  (интервал 300 мс работает и во время подхода, не только во время отдыха) и по
  `AppState → active`.
- Убитый процесс: нажатия на часах всё равно доставляются broadcast-ресиверам
  (манифестный receiver не требует живого JS). Значения корректировок
  восстанавливаются из extras; `commit-set` сохраняется в SharedPreferences и
  применяется при следующем запуске приложения — как и остальные pendingAction
  (`skip`/`extend`/`start`/`finish-exercise`).
- Начало отдыха по будильнику, звуки и вибрации — без изменений
  (`docs/rest-timer-lock-screen-research.md`).

## Изменения

- `modules/ironrise-rest-timer/android/.../IronriseRestTimerModule.kt` —
  константы `ACTION_FINISH_SET`/`ACTION_COMMIT_SET`/`ACTION_ADJUST_*`/
  `ACTION_CANCEL_SET`, канал `ironrise-active-set-v1`, id 40108/40109,
  карточки-псевдокнопки 40121–40125 и 40131/40132, request codes 40118–40120,
  функции `showActiveSetNotification` (contentIntent + подсказка),
  `showSetResultNotification` (серия карточек с `setSortKey`),
  `postResultActionCard`, `clearActiveSetNotification`,
  `cancelResultActionCards`, `cancelRestActionCards`, `setActionPendingIntent`,
  `activeSetStateFromIntent`, `formatSetWeightKg`; лейблы отдыха
  «Следующий подход»/«Следующее упражнение». Раскладка «Ещё»
  (`ACTION_MORE`, `resultLayout`, `SET_RESULT_LAYOUT_COUNT`) удалена.
- `.../RestTimerActionReceiver.kt` — обработка действий (включая
  `ACTION_CANCEL_SET`), статика значений ввода результата, очистка всех
  карточек результата по commit/cancel, очистка карточек отдыха по
  `ACTION_START`.
- `.../RestTimerCompletionReceiver.kt` — тихие карточки «Следующий подход»
  (40131) и «Следующее упражнение» (40132) с contentIntent `ACTION_START`,
  канал `ironrise-rest-complete-actions-v1`.
- `modules/ironrise-rest-timer/src/index.ts` — `showNativeActiveSetNotification`,
  `clearNativeActiveSetNotification`, `NativeActiveSetPayload`, kind `commit-set`.
- `app/workout.tsx` — эффект зеркала активного подхода, обработка `commit-set`
  (общий код завершения с UI), поллинг во время подхода, авто-переход к
  следующему упражнению после «Следующее упражнение», очистка при завершении
  тренировки. Логика JS не менялась: набор kind `consumePendingAction`
  прежний (`skip`/`extend`/`start`/`finish-exercise`/`commit-set`).

## Huawei Watch GT6: зеркалирование уведомлений

Обновлено после проверки на устройстве: уведомления IronRise приходят на телефон, но не появляются на Huawei Watch GT6.

Причина: Huawei Health зеркалирует на часы только ОБЫЧНЫЕ уведомления панели уведомлений. Постоянные (ongoing) уведомления — к ним относится отсчёт отдыха — на часы не передаются. Уведомления подхода и результата также были ongoing и не доходили.

Исправление: уведомления «Подход N из M» и «Результат подхода N» больше не ongoing (они пере-постятся при каждом изменении состояния, постоянность не нужна). Отсчёт отдыха остаётся ongoing на телефоне — живой таймер на часах недоступен, но ключевые события цикла зеркалируются: «Подход N» (кнопка «Завершить подход»), «Результат подхода» (кнопки ввода), «Отдых завершён» («Следующий подход»/«Следующее упражнение»).

Чек-лист настройки Huawei Health (если уведомления всё ещё не доходят):
1. Настройки телефона → Доступ к уведомлениям → включить «Huawei Здоровье».
2. Huawei Health → Устройства → часы → Уведомления → включить «Синхронизировать уведомления с телефона на часы» и включить IronRise в списке приложений.
3. Там же: Режим уведомлений → «Уведомлять на обоих устройствах» (иначе при разблокированном телефоне часы молчат — критично во время тренировки).
4. На часах: выключить «Не беспокоить» и «Не беспокоить, когда не надеты» (GT6).
5. Разрешить Huawei Health работу в фоне (закрепить в недавних задачах / защита соединения), иначе зеркалирование умирает при чистке памяти.
