# Управление тренировкой с часов Huawei (зеркалируемые уведомления)

## Зачем

Huawei Watch GT 6 (HarmonyOS) не запускает приложения Android-телефона напрямую:
уведомления Android зеркалируются на часы через Huawei Health. Это единственный
канал управления тренировкой «не доставая телефон». Подтверждённые ограничения
(см. `docs/huawei-gt6-research-notes.md`):

- кнопки-действия уведомления отображаются на часах и работают;
- удалённый ввод текста (`RemoteInput`) на зеркальных уведомлениях не
  поддерживается — ввод результата подхода сделан кнопками-корректировками;
- на зеркале видно до **трёх** действий в ряду, поэтому набор кнопок
  переключаемый: «Ещё» листает корректировки по кругу.

## State machine уведомлений

```
[Подход выполняется] --«Завершить подход»--> [Ввод результата] --«Готово»--> [Отдых] --«Следующий подход»/«Следующее упражнение»--> ...
        ^                                            |
        |______________________ «Отменить» не нужен: раскладка возвращается «Ещё» (см. ниже)
```

Фактическая петля корректировок во «Вводе результата»:

```
layout 0: [+5 кг]     [Ещё] [Готово]
layout 1: [−5 кг]     [Ещё] [Готово]
layout 2: [+1 повтор] [Ещё] [Готово]
layout 3: [−1 повтор] [Ещё] [Готово]
layout 4: [Отменить]  [Ещё] [Готово]
```

«Ещё» (`ACTION_MORE`) переключает раскладку по кругу, «Готово»
(`ACTION_COMMIT_SET`) доступна в любой раскладке, «Отменить»
(`ACTION_CANCEL_SET`) возвращает к зеркалу подхода. Ограничение ≤3 действий
соблюдается: в каждом уведомлении ровно три `addAction`.

1. **Подход выполняется.** JS вызывает `showNativeRestCountdown`-подобную
   `showActiveSetNotification({ exerciseName, setIndex, setsCount,
   planWeightKg, planReps, exerciseIndex, exercisesCount, exerciseId })` в
   момент, когда `activeSet` появляется (`startSet`, авто-старт следующего
   подхода из нативного уведомления, восстановление черновика). Заголовок
   «Подход N из M · <Упражнение>», текст «План: 80 кг × 8 · Упражнение 2 из 5»,
   одно действие «Завершить подход» (`ACTION_FINISH_SET`). Кнопки отдыха
   («+30 сек») в этом состоянии не показываются. Уведомление обновляется при
   смене упражнения/подхода тем же вызовом (same notification id).
2. **Ввод результата.** `RestTimerActionReceiver` ловит `ACTION_FINISH_SET`,
   снимает уведомление подхода и постит «Результат подхода N · <Упражнение>» с
   текстом «80 кг × 8» и переключаемой раскладкой корректировок. Текущие
   значения хранятся в статике receiver'а (`currentWeightKg`, `currentReps`,
   `resultLayout`), инициализируются планом и дублируются в extras каждого
   `PendingIntent` — если процесс умер, следующее нажатие восстанавливает
   значения из extras. «Готово» → `ACTION_COMMIT_SET`; корректировки
   пересчитывают значение и пере-постят то же уведомление; шаг веса — 5 кг,
   повторов — 1, минимум 0 кг и 1 повтор.
3. **Отдых.** `ACTION_COMMIT_SET` сохраняет pendingAction с kind `commit-set`
   и финальными weight/reps (механизм `savePendingAction`/`consumePendingAction`
   — событий в модуле нет, JS опрашивает `consumeNativeRestTimerAction`), снимает
   уведомление результата. JS применяет значения тем же кодом, что и завершение
   подхода из интерфейса (`finishSetFromWatch` → общий `completeSetDraft` с
   `finishSetFromWidget`), после чего штатно запускается существующий отсчёт
   отдыха с действиями «Пропустить», «+30 секунд» и primary-действием
   «Следующий подход» / «Следующее упражнение».
4. **Отмена.** Раскладка 4 показывает «Отменить» (`ACTION_CANCEL_SET`):
   receiver снимает уведомление результата и заново показывает уведомление
   подхода с планом — значения сбрасываются к плану, JS-состояние не меняется
   (подход продолжает выполняться).

## Что работает при свёрнутом и убитом приложении

- Свёрнутое приложение (процесс жив): нативные ресиверы обрабатывают нажатия и
  пере-постят уведомления сами; JS подхватывает `commit-set` поллингом
  (интервал 300 мс работает и во время подхода, не только во время отдыха) и по
  `AppState → active`.
- Убитый процесс: нажатия на часах всё равно доставляются broadcast-ресиверам
  (манифестный receiver не требует живого JS). Значения корректировок
  восстанавливаются из extras; `commit-set` сохраняется в SharedPreferences и
  применяется при следующем запуске приложения — как и остальные pendingAction
  (`skip`/`extend`/`start`/`finish-exercise`).
- Начало отдыха по будильнику, звуки и вибрации — без изменений
  (`docs/rest-timer-lock-screen-research.md`).

- `modules/ironrise-rest-timer/android/.../IronriseRestTimerModule.kt` —
  константы `ACTION_FINISH_SET`/`ACTION_COMMIT_SET`/`ACTION_ADJUST_*`/
  `ACTION_CANCEL_SET`/`ACTION_MORE`, канал `ironrise-active-set-v1`, id
  40108/40109, функции `showActiveSetNotification`, `showSetResultNotification`,
  `clearActiveSetNotification`, `setActionPendingIntent`,
  `activeSetStateFromIntent`, `formatSetWeightKg`; лейблы отдыха
  «Следующий подход»/«Следующее упражнение».
- `.../RestTimerActionReceiver.kt` — обработка новых действий (включая
  `ACTION_CANCEL_SET`), статика значений ввода результата, переключаемая
  раскладка.
- `modules/ironrise-rest-timer/src/index.ts` — `showNativeActiveSetNotification`,
  `clearNativeActiveSetNotification`, `NativeActiveSetPayload`, kind `commit-set`.
- `app/workout.tsx` — эффект зеркала активного подхода, обработка `commit-set`
  (общий код завершения с UI), поллинг во время подхода, авто-переход к
  следующему упражнению после «Следующее упражнение», очистка при завершении
  тренировки.

## Huawei Watch GT6: зеркалирование уведомлений

Обновлено после проверки на устройстве: уведомления IronRise приходят на телефон, но не появляются на Huawei Watch GT6.

Причина: Huawei Health зеркалирует на часы только ОБЫЧНЫЕ уведомления панели уведомлений. Постоянные (ongoing) уведомления — к ним относится отсчёт отдыха — на часы не передаются. Уведомления подхода и результата также были ongoing и не доходили.

Исправление: уведомления «Подход N из M» и «Результат подхода N» больше не ongoing (они пере-постятся при каждом изменении состояния, постоянность не нужна). Отсчёт отдыха остаётся ongoing на телефоне — живой таймер на часах недоступен, но ключевые события цикла зеркалируются: «Подход N» (кнопка «Завершить подход»), «Результат подхода» (кнопки ввода), «Отдых завершён» («Следующий подход»/«Следующее упражнение»).

Чек-лист настройки Huawei Health (если уведомления всё ещё не доходят):
1. Настройки телефона → Доступ к уведомлениям → включить «Huawei Здоровье».
2. Huawei Health → Устройства → часы → Уведомления → включить «Синхронизировать уведомления с телефона на часы» и включить IronRise в списке приложений.
3. Там же: Режим уведомлений → «Уведомлять на обоих устройствах» (иначе при разблокированном телефоне часы молчат — критично во время тренировки).
4. На часах: выключить «Не беспокоить» и «Не беспокоить, когда не надеты» (GT6).
5. Разрешить Huawei Health работу в фоне (закрепить в недавних задачах / защита соединения), иначе зеркалирование умирает при чистке памяти.
