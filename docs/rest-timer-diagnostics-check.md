# Диагностика таймера отдыха и Android-уведомлений

## Проверка Expo web

Проверка предпросмотра на `http://127.0.0.1:8081/` 26 августа 2026 года подтвердила загрузку приложения без ошибки, связанной с логикой таймера отдыха. В консоли зафиксированы существующие web-ограничения `expo-notifications`, предупреждения о deprecated web-свойствах и responder-обработчиках React Native, а также предупреждение о fallback-анимации. Они не относятся к нативному Android-уведомлению.

В web-консоли появились штатные записи инициализации приложения. Проверить действия системного Android-уведомления в этом окружении нельзя: браузерный Expo runtime не загружает Kotlin-модуль `IronriseRestTimer` и не имеет Android notification manager.

## Записи, ожидаемые на Android

| Источник | Тег или префикс | Назначение |
|---|---|---|
| JavaScript | `[IronRiseRestTimer]` | Старт отдыха, планирование нативного уведомления, получение действия, фактическое завершение отдыха. |
| Android native | `IronRiseRestTimer` | Публикация и очистка countdown-уведомления, действие пользователя, продление отдыха, завершение отдыха и запись/чтение pending action. |

Для устройства с Android нужно отфильтровать Logcat по тегам `IronRiseRestTimer` и `ReactNativeJS` либо выполнить `adb logcat -v time IronRiseRestTimer:D ReactNativeJS:I *:S`.
